# Coh-Metrix labels: open questions

Context: we are cleaning up the label scheme. Every index has

- `label_v3` / `label_v2`: the original Coh-Metrix label (concept identity),
- a TTLab label that gets a suffix whenever we deviate from the original in
  *meaning* (different corpus, lexicon, word list, model, formula or library),
  but not for preprocessing differences (tokenization, sentence splitting,
  POS, parsing, lemmas, syllables).

Test for a suffix: *If our NLP preprocessing were perfect, would we reproduce
the original value?* If not, the label needs a suffix that names the reason.

For the items below we cannot tell from the repository what the right suffix
is, because the provenance of a list or rule set is not documented in the
code. Until they are answered, these indices keep their previous names as the
public label (`SMTEMP_gptlist`, `DRNEG_gptlist`, `SMCAUSv_wordnet`, ...); for
the situation model inventories, the German internal label names the resource
actually used (`_germanet`, or `_seedlist` without GermaNet). Line numbers refer
to `src/main/python/duui.py` before the label change and may have shifted.

## 1. `SMTEMP_gptlist`

- Current label: `SMTEMP_gptlist` (`duui.py:6347`)
- What the code does: rule-based tense/aspect detection from morphology and
  dependencies (`_detect_german_tense` :4288, `_detect_english_tense` :4544,
  `cm_smtemp` :4956). There is no word list involved.
- Question: Were these detection rules generated by GPT? If yes, is
  `_gptlist` the right name, given that there is no list? If the rules are
  hand-written, SMTEMP is a preprocessing-level approximation and would get
  no suffix.

## 2. `DRNEG_gptlist`

- Current label: `DRNEG_gptlist` (`duui.py:6607`)
- What the code does: counts a token as negation if its dependency label is
  `NEG`/`NG` **or** its lemma is in `_DE_NEGATION_LEMMAS` (:1480) /
  `_EN_NEGATION_LEMMAS` (:1497).
- Question: Were these two lemma sets generated by GPT? There is no
  provenance comment (unlike the connectives list, see 3).

## 3. Connectives (`CNC*_gptlist`)

- Documented in code: "List has been generated by ChatGPT 4o based on the
  Coh-Metrix index definitions" (`duui.py:2651`).
- Question: Does this hold for both the EN and the DE lists, and were the
  lists edited manually afterwards? (Only to confirm; the label looks right.)

## 4. Situation model causal/intentional inventories (`SMCAUSv`, `SMCAUSvp`, `SMINTEp`, `SMCAUSr`, `SMINTEr`)

- Current labels: `*_wordnet` (EN) / `*_germanet` (DE)
- The original Coh-Metrix also uses WordNet to classify causal and intentional
  verbs (`docs/cohmetrix_measures.md:92`), so for EN the *resource* is the
  original. The *verb classes* are our own selection:
  - EN: hyponyms of `cause.v.01` (causal) and `intend.v.01` + `plan.v.01`
    (intentional) (`duui.py:3763` ff.).
  - DE: GermaNet expansion of the seeds `verursachen`, `bewirken`, `auslösen`
    (causal) and `beabsichtigen`, `planen` (intentional), plus hand-picked
    seed sets `_DE_CAUSAL_SEED` / `_DE_INTENTIONAL_SEED` (:3738-3742).
- The causal and intentional **particle** lists (EN :3796/:3805, DE
  :3819/:3828) are used by `SMCAUSvp`, `SMCAUSr` and `SMINTEr`; their
  provenance is not documented.
- Under the label rules, the EN internal label gets no suffix if the original
  resource is used as in the original. Here the resource is the same
  (WordNet), but the verb class selection is ours, so a suffix is probably
  still needed in both the internal and the public label; which one depends on
  the answers below.
- Questions:
  - Who chose the seed synsets/lemmas and the particle lists (by hand, GPT,
    taken from a paper)?
  - Is there a source for how the original Coh-Metrix selected its causal and
    intentional verb classes from WordNet?

## 5. Flesch indices via textstat (`RDFRE_textstat`, `RDFKGL_textstat`)

- textstat is used from the fork `felixvoll/textstat@v0.7.12-post2`
  (`requirements.txt:57`), with `textstat.set_lang(lang)` (`duui.py:4983`).
- The original Coh-Metrix defines RDFRE/RDFKGL from its own DESSL and DESWLsy
  with the English Flesch constants
  (`docs/cohmetrix_measures_of_text_readability_and_easability.md:11`).
- Question: For `lang="de"`, does the fork switch to German constants
  (Amstad: `180 - ASL - 58.5 * ASW`)? If yes, the DE value is a different
  formula, not just a different implementation, and the label should say so.
- Question: Which syllable counter does the fork use? (Our DESWLsy uses
  pyphen hyphenation points, `duui.py:440-447`.)

The label rules themselves are documented in `README.md` under
"Index labels".
